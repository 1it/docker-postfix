## v0.1.4

### Bug Fixes

- **Authenticated submission actually accepts logins** — port 587 answered `554 5.7.1 Client host rejected: Access denied` as soon as a client connected. `smtpd_delay_reject=no` applied `permit_sasl_authenticated,reject` before AUTH, so the password was never checked and adding the client to `MY_NETWORKS` did nothing. Submission now delays that decision until after SASL, requires AUTH only over TLS, and permits relay for authenticated clients.
- **Let's Encrypt certificate matches the SMTP hostname** — HTTP-01 was requested for `DOMAIN`. That name is the DKIM domain and is often behind a CDN, so the challenge never reached the container (a proxied apex returns 404). The certificate is now issued for `MAILNAME`. Additional names still come only from `LETSENCRYPT_EXTRA_DOMAINS`, and each of them must resolve to this host on port 80.

### Upgrade Notes

- Certificates already stored under `/etc/letsencrypt/live/<DOMAIN>/` are not reused when `MAILNAME` differs from `DOMAIN`. The container issues a new certificate for `MAILNAME`, or falls back to the self-signed cert if issuance fails.
- Clients on port 587 authenticate with `SMTP_AUTH_USERS`. They do not need to be listed in `MY_NETWORKS`.
